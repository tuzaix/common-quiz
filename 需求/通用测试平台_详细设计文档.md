# 通用测试平台详细设计文档 (Detailed Design)

## 1. 核心模块详细设计

### 1.1 动态题目引擎 (Dynamic Question Engine)

为了支持复杂的题目逻辑，我们需要更细粒度的配置项。

#### 1.1.1 题目数据结构扩展
```typescript
interface Question {
  id: string;
  type: 'single_choice' | 'multi_choice' | 'scale' | 'slider' | 'image_picker';
  content: {
    text: string; // 题干
    media?: { type: 'image' | 'video', url: string }; // 题目配图/视频
  };
  options: Array<{
    id: string;
    label: string;
    value: number | string; // 分数或标识
    dimensionKey?: string; // 该选项特定的维度加分（可选）
    jumpTo?: string; // 选此项后跳转到指定题目ID
    exclusive?: boolean; // 多选中的互斥项（如“以上都不是”）
  }>;
  settings: {
    required: boolean;
    minSelections?: number; // 多选最少选几项
    maxSelections?: number; // 多选最多选几项
    timeLimit?: number; // 倒计时（秒）
  };
}
```

#### 1.1.2 渲染组件拆分
建议创建 `d:\develop\realme\frontend\src\components\engine` 目录：
- `QuestionContainer.vue`: 负责进度条、题目切换动画、上一题/下一题逻辑。
- `QuestionTypeRegistry.js`: 策略模式，根据 type 映射到具体组件。
- `inputs/SingleChoice.vue`
- `inputs/MultiChoice.vue`
- `inputs/ScaleSlider.vue`

### 1.2 计分与逻辑引擎 (Scoring & Logic Engine)

#### 1.2.1 复杂跳转逻辑 DSL
在 `ProjectConfig` 中增加 `logicFlow` 字段，支持条件判断：
```json
"logicFlow": {
  "q1": {
    "default": "q2",
    "rules": [
      { "condition": "answer == 'A'", "next": "q5" },
      { "condition": "answer == 'B' && userProfile.gender == 'male'", "next": "q3" }
    ]
  }
}
```
**实现方案**：使用轻量级表达式解析库（如 `filtrex` 或简单的 `Function` 构造器封装）来评估 `condition`。

#### 1.2.2 维度计算器 (Dimension Calculator)
对于 MBTI 或大五人格，需要支持“标准化分”转换（T分转换）：
```javascript
// 示例：将原始分转换为常模分
function normalizeScore(rawScore, mean, stdDev) {
  return ((rawScore - mean) / stdDev) * 10 + 50; 
}
```
配置项应支持：
```json
"dimensionRules": {
  "openness": {
    "initialValue": 0,
    "formula": "sum(options.value)", // 或 "avg(options.value)"
    "normalization": { "mean": 35.5, "stdDev": 5.2 } // 可选：常模转换
  }
}
```

### 1.3 结果页与分享图 (Result & Sharing)

#### 1.3.1 结果匹配算法
不仅支持单一维度，还应支持**组合维度**匹配：
```json
"resultMatchers": [
  {
    "priority": 100,
    "logic": "dimension.E > 50 && dimension.N > 50", // 外向且神经质
    "resultId": "EN_Type"
  },
  {
    "priority": 1,
    "logic": "true", // 兜底结果
    "resultId": "Default_Type"
  }
]
```

#### 1.3.2 动态分享图配置 (Canvas DSL)
为了避免每次修改 Result.vue，定义一套 JSON 描述的 Canvas 布局：
```json
"shareCardLayout": {
  "width": 750,
  "height": 1334,
  "background": "https://cdn.../bg.png",
  "layers": [
    { "type": "text", "text": "{userName}", "x": 50, "y": 100, "fontSize": 32, "color": "#000" },
    { "type": "image", "url": "{resultAvatar}", "x": 200, "y": 300, "width": 300, "height": 300 },
    { "type": "chart", "chartType": "radar", "data": "{dimensionScores}", "x": 100, "y": 700, "width": 500, "height": 400 },
    { "type": "qrcode", "url": "{shareLink}", "x": 550, "y": 1100, "width": 150, "height": 150 }
  ]
}
```
**实现方案**：编写一个通用的 `CanvasRenderer.js`，解析上述 JSON 并调用 `canvas` API 绘制，最后输出 Base64。

## 2. 后端与运维架构 (Backend & Ops)

### 2.1 多租户与项目隔离
为了支持多个测试项目共存，文件结构建议如下：
```
/backend
  /data
    /projects
      /mbti
        config.json
        questions.json
        results.json
        assets/
      /psych_age
        config.json
        ...
    /global
      cards.db (SQLite)
      users.db
```
API 路由需升级为支持 ProjectID：
- `GET /api/v1/projects/:projectId/config`
- `POST /api/v1/projects/:projectId/submit`

### 2.2 防刷与安全
- **接口限流**：针对 `submit` 接口，单 IP 限制 10 次/分钟。
- **卡密锁**：卡密在验证时通过 Redis (或内存) 加分布式锁，防止并发请求导致的一卡多用。

### 2.3 自动化部署流 (CI/CD)
建议增加 `scripts/deploy_project.js` 脚本：
1. 管理员在本地编辑好 `config.json`。
2. 运行 `npm run deploy --project=mbti`。
3. 脚本自动将配置上传至服务器指定目录，并刷新 Nginx 缓存（如有）。

## 3. 开发路线图 (Roadmap)

### 第一阶段：核心引擎重构
1. 提取 `QuizStore` 中的逻辑到 `ScoringService`。
2. 创建 `ProjectConfig` 定义文件，替换硬编码的 `questions.json` 引用。
3. 实现基础的 `DynamicQuestion` 组件。

### 第二阶段：高级功能
1. 实现 Canvas DSL 渲染器，替代目前的 HTML2Canvas 截图方案（截图方案兼容性差，Canvas 直绘更稳定）。
2. 添加多维度组合匹配逻辑。

### 第三阶段：管理后台
1. 开发可视化的“题目编辑器”和“逻辑连线图”。
2. 集成数据看板（PV/UV/转化率/平均分）。
