# 通用测试平台技术架构文档

## 1. 系统架构概览

本系统采用 **配置驱动 UI (Configuration-Driven UI)** 的架构模式。前端应用是一个通用的“渲染器”，它读取后端的 JSON 配置文件，动态生成题目界面、执行计分逻辑并渲染结果页。

### 技术栈
- **Frontend**: Vue 3 (Composition API), Pinia (State Management), Tailwind CSS (Styling).
- **Backend**: Node.js / Serverless Functions (API 托管, 卡密验证).
- **Storage**: JSON Files (Config), SQLite/MySQL (Cards/User Data).
- **Tools**: html2canvas (分享图生成), ECharts/Chart.js (图表).

## 2. 核心数据模型 (Data Schema)

所有的测试项目核心逻辑由三个 JSON 对象定义：`ProjectConfig`, `QuestionData`, `ResultConfig`。

### 2.1 ProjectConfig (项目配置)
```json

  "meta": {
    "title": "心理年龄测试",
    "description": "通过潜意识选择揭示你的真实心理年龄",
    "coverImage": "/assets/covers/psych_age.jpg",

  "settings": {
    "accessMode": "public", // public | code_required
    "shuffleQuestions": true,

  }

```

### 2.2 QuestionData (题库数据)
```json

    "type": "likert_5",
    "options": [
      { "value": 1, "label": "非常不同意" },
      { "value": 5, "label": "非常同意" }

  },
  "dimensions": [ // 维度定义
    { "key": "openness", "name": "开放性" },

  "questions": [
    {
      "id": "q1",

      "dimension": "openness",

```

### 2.3 ResultConfig (结果与计分配置)
```json

      "condition": "score < 25", // 简单表达式

    }

  "shareCard": {
    "layout": "classic_radar", // 布局模板
    "elements": {
      "showScore": true,
      "showRadar": true,
      "showQRCode": true
    }
  }
}
```

## 3. 前端模块设计

### 3.1 动态题目渲染器 (`QuestionRenderer.vue`)
- **输入**: 单个 `question` 对象。
- **职责**: 根据 `type` 字段动态加载 `ScaleInput`, `RadioInput`, `ImageSelect` 等子组件。
- **输出**: `emit('answer', { id, value })`。

### 3.2 计分引擎服务 (`ScoringService.js`)
这是一个纯 JS 逻辑层，不依赖 UI。

### 3.3 结果页工厂 (`ResultFactory.vue`)
- **输入**: `calculationResult` (计算结果)。
- **职责**:
    1. 遍历 `resultRules`，找到第一个匹配的规则。
    2. 渲染对应的结果文案。
    3. 根据配置决定是否显示雷达图、柱状图。
    4. 包含 `ShareCardGenerator` 组件用于生成图片。

## 4. 后端接口设计 (API)

为了支持通用的卡密系统，后端 API 保持统一：

- `GET /api/project/:id`: 获取项目配置（前端缓存）。
- `POST /api/verify-card`: 验证卡密（通用逻辑，带上 projectId）。
- `POST /api/generate-cards`: 管理员生成卡密。
- `GET /api/admin/stats`: 获取访问量、完成率等统计。

## 5. 扩展性设计 (Plugin System)
为了支持特殊需求（如复杂的运势计算），系统支持**脚本注入**。
在 `ResultConfig` 中可以配置 `scriptUrl`，前端加载该外部 JS，并调用约定的 `customCalculate(answers)` 函数。这允许开发者在不修改核心代码的情况下，通过编写独立 JS 文件来扩展计分逻辑。
